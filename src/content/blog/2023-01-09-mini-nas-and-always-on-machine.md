起因很朴素：资料库把那块 1.8T 的机械盘吃满了。

紧急下单了一块 8T 硬盘。到手之后，琢磨的第一件事不是怎么装，是装在哪。

## 不想挂在家用机上

直接插在家用机上当然最省事。但那样有两个问题：机器不开机就访问不到；而且这台机器上已经挂着一块 2T 了。

我想要的是另一种形态 —— 硬盘挂在一台低功耗、可以一直开着的机器上，然后从外面随时能访问。带宽如果哪天升级了，甚至可以在外面直接看家里的视频。

最后选的方案很轻：一个 USB DECK，通过 USB 3.0 接到刷了梅林固件的路由器上，用梅林自带的 NFS 把盘映射出去。

路由器本来就是 7×24 开着的，等于零新增功耗。步骤也就四步：

1. 更新梅林固件，确认 NFS 可用，顺便考虑打开 swap；
2. 接 USB 3.0 的 DECK，先测一遍磁盘性能；
3. NFS 映射网络磁盘；
4. 家用机把存量资料拷上去，之后新资料直接下到它上面。

## 为什么是 NFS 不是 SMB

一开始想当然用 SMB，然后才了解到它在随机读取上的不足 —— 这也是一般 NAS 更倾向 NFS 的原因。

在家里 NFS 用得很舒服。拷贝速度谈不上给力，局域网只跑到 10 MB/s 左右，但它的 IO 方式和 Windows 本地磁盘很接近，媒体库那边接入也方便。

代价是 NFS 在 Windows 上的服务端选择极少。我用的那个是相当古早的软件，除此之外基本只剩 Windows Server 一条路。这个协议本身也偏冷门，NAS 系统喜欢它，桌面世界不太理它。

真正的问题出在远程访问上：远程 + 无线的时候，带宽始终在 4M 左右徘徊，怎么都上不去；换成远程 + 有线就能跑满。所以"随时随地看家里的视频"这件事，目前卡在无线这一环，还没解决。

## 顺手解决的媒体库

盘一大，管理需求马上就来了。两三 T 的东西堆在一起，想找刚才看到的某一个，鼠标都要滚烂。

后来摸到了 kodi ——一个基于文件的媒体管理系统，按文件建索引，最终呈现出来的东西接近一个视频站的片库。这个问题显然已经有很多人趟过了。

配套的还有两个：TinyMediaManager 负责刮削元数据、生成 kodi 能直接读的数据库文件，还能顺手整理文件名和目录结构；ChineseSubFinder 负责补字幕，它把已知的几个字幕站都接上了，也能对接主流的媒体管理系统。

GitHub 上这一类工具齐全得有点夸张，能看出这个领域里 geek 的狂热程度。

## 另一台：永远连得上的机器

和 NAS 并列的第二件常开设施，是一台随时能远程连上的桌面机器。

技术栈也不复杂：

- **网络入口**：frp 打通公网访问；
- **远程串流**：moonlight / sunshine，延迟低到可以直接玩游戏；
- **控制层**：一个 node 写的小 web 服务，加一块支持"来电自动开机"的远程插板 —— 断电重启之后机器会自己起来，不需要人在家。

最后一条是整套东西的关键。远程访问的方案有的是，但只要有一次"机器关了，而我在外面"，这套设施在心理上就不成立了。插板解决的就是这一件事。

## 边界

这套东西的定位是"够用"，不是 NAS 方案。

路由器 USB 口的性能是有天花板的，10 MB/s 这个数字换到正经 NAS 上会很难看。真要跑多用户、要冗余、要快照，这套方案一条都不满足。

它成立的前提是：只有我一个用户，数据丢了不至于要命，而我更在意的是"这块盘一直在线"。
